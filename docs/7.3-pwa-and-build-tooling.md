# 7.3. PWA and Build Tooling

Valyrian includes build helpers in `valyrian.js/node` and a service worker runtime manager in `valyrian.js/sw`.

Adoption tip: add these after core routing + data + SSR behavior is stable.

For runtime update orchestration APIs, see [./7.3.1-sw-runtime.md](./7.3.1-sw-runtime.md).

## Icons and Manifest Generation

Use `icons()` to generate app icon assets and related metadata from one source image.

```js
import { icons } from "valyrian.js/node";

await icons("./assets/logo.png", {
  iconsPath: "./public/icons",
  linksViewPath: "./src/generated",
  appName: "My Valyrian App"
});
```

When `linksViewPath` is set, `icons()` writes the links view in three formats in that same folder:

* `links.js`: CommonJS output with a flat array of `link` vnodes.
* `links.jsx`: JSX component output with a named `Links` export for projects that use the automatic JSX runtime.
* `links.tsx`: TSX component output with a named `Links` export for TypeScript projects that use the automatic JSX runtime.

Choose the generated format that matches your build environment.

## Service Worker File Generation

```js
import { sw } from "valyrian.js/node";
import pkg from "./package.json";

sw("./public/sw.js", {
  version: pkg.version,
  name: "my-app-cache",
  criticalUrls: ["/", "/index.html", "/dist/main.js"],
  optionalUrls: ["/offline.html"],
  offlinePage: "/offline.html"
});
```

`urls` remains supported for compatibility, but `criticalUrls` and `optionalUrls` are preferred.

## JavaScript and TypeScript Bundling (`inline`)

```js
import fs from "fs";
import { inline } from "valyrian.js/node";

const bundle = await inline("./src/index.tsx", { compact: true });
fs.writeFileSync("./public/main.js", bundle.raw);
```

For TS/TSX entries, `inline` validates types by default (`noValidate: true` disables this).

`inline(...)` returns `{ raw, map, file }`.

For JavaScript and TypeScript entries, `map` contains a source map as a data URI. Source maps can expose source code
and local paths, so production builds should usually publish only `raw` unless you intentionally want clients to access
the source map.

Supported `inline` options:

* `compact`: minifies JavaScript and TypeScript output with Terser, and CSS output with CleanCSS defaults.
* `bundle`: controls esbuild bundling for JavaScript and TypeScript entries. The default is `true`.
* `noValidate`: skips the default TypeScript validation step for TS/TSX entries.
* `declarationDir`: enables declaration-only TypeScript output in the provided directory during validation.
* `tsc`: passes extra options to the TypeScript validation step used by `inline`.
* `esbuild`: passes safe esbuild options through to the bundling step. `inline` owns `write`, `sourcemap`, entry inputs,
  output paths, bundling/minify flags, loaders and JSX runtime settings so it can keep returning `{ raw, map, file }`.
  Use this for safe passthroughs such as `jsxDev`, `target` or `define`.
* `terser`: passes extra options to Terser when `compact` is enabled for JavaScript and TypeScript entries.
* `cleanCss`: passes extra options to CleanCSS for CSS entries.

## CSS Bundling and Purging

```js
import { inline } from "valyrian.js/node";

const cssBundle = await inline("./src/app.css");
const criticalCss = await inline.uncss([renderedHtml], cssBundle.raw);
```

`inline.uncss` removes unused selectors using rendered HTML as input.

`inline.uncss(renderedHtml, css, options)` accepts PurgeCSS options for selector extraction and safelists. It owns the
generated `content` and `css` inputs, and accepts `cleanCss` for the final minification pass.
